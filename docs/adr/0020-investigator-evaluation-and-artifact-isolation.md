# ADR 0020: Actual investigator evaluation and isolated saved artifacts

**Delivery-sequencing update — 2026-10-16:** [ADR 0022](0022-sprint-06-readiness-and-sprint-07-diagnostics.md) replaces only the original S6/S7 acceptance timing: S6 local readiness/handoff, S7 actual Azure diagnostics and owner quality decision. The original decision text and evidence below remain historical; provider/architecture/security boundaries are unchanged.

- Status: Proposed in #39; owner review pending
- Date: 2026-10-15
- Scope: Sprint 5 offline integration/scoring, not a quality/release or live-run approval

## Context

#14 scores hand-authored v1 candidates; #37/#38 now produce actual protected v2 workflow/CLI outputs. Evaluation must exercise that assembled path without introducing expected answers into its grants, tools, corpus or model. Execution, publication/support, candidate correctness, citation existence and independent human support need distinct accounting. Paid calls and actual human endorsement cannot be fabricated.

## Decision

Keep the evaluator repository-only. Execute a fixed predeclared development protocol through a separate observed-only script process and the public CLI. The evaluator parent owns labels; the child receives a generator case and mechanical fault selector, and the fake uses observed source gaps and a constant negative-example cause rather than expected answers. Do not import evaluator modules into runtime or the child. Scope/source/transmission and generated-response protection remain in existing application boundaries.

Add a versioned v2 output scorer that reuses #14's label/claim-support rubric through a strict candidate projection and an explicit authorized-citation set. Preserve v1 defaults and frozen artifact bytes. Report all attempts, failures, partial inputs, withheld/missing outputs, unknown usage and separate cohort denominators. Predeclared engineering boundary checks can pass while diagnostic/human/release acceptance stays blocked.

Save private hash-bound observed/result/execution/source artifacts, a deterministic predeclared support sample and initially empty actual review records. Write the manifest last, bind recursive implementation/lock/protocol/source identities and require the recorded checkout for rescoring. Rescore without model/tool/process dispatch. New actual human decisions bind to exact sampled claims and create a new score artifact, preserving disagreements and originals. Runtime scripted support does not count as human evaluation.

Live end-to-end work remains explicitly not run until the owner declares run scope, source/transmission rights, known spending/allowance, quality criteria and review coverage. No fake provider or historical connector success can satisfy it. S6 retains comparative measurement, human review, release criteria and recovery/security acceptance. No new dependency, runtime capability, provider or operational grant is added.

## Alternatives and consequences

Copying expected labels into a fake/model or using fake support as human credit would invalidate the study. Scoring only completed reports would hide reliability failures. Rebuilding all retrieval/tool metrics would duplicate accepted contracts. Replaying models during rescoring would change evidence and spending. Scope-only report export would bypass inherited authority. These alternatives are rejected.

The mechanism proves local orchestration, artifact integrity and exercised boundaries. It is not an OS sandbox or a proof of real model robustness/diagnosis/operational usefulness. Exported artifacts require their authorized local audience/retention; hashes do not grant access. Revisit this ADR before real-source or hosted evaluation, authenticated reviewer integration, actual-provider comparisons, new cohorts/arms or any final-test access.
