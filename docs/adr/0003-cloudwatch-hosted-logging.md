# ADR 0003: Amazon CloudWatch Logs for hosted application logging

- **Status:** Accepted platform selection by the owner, 2026-09-24; deployment pending.
- **Context:** The owner wants a hosted logging platform. Terraform and EC2 are already the approved cloud direction. Console-only logging does not satisfy hosted acceptance.
- **Decision:** Use Amazon CloudWatch Logs for TRACE application logs and Logs Insights for search. Keep Python standard-library logging, structured JSON and redaction in the application. Use the managed CloudWatch agent on EC2 for delivery; do not implement a custom log transport, storage or search platform.
- **Boundary:** Application JSON stderr → deployment-managed local file → CloudWatch agent → environment-specific CloudWatch log group. The EC2 launch/service wrapper must capture stderr into the configured file; the agent does not automatically collect arbitrary process stderr. Select and test log rotation, file permissions and agent checkpoint persistence during deployment.
- **Identity:** Use an EC2 instance role, not embedded access keys. Terraform owns log-group creation and retention; the collector receives scoped stream/write permissions. Query access is separate from collection access. Do not grant the application broad CloudWatch administration.
- **Cost/data:** The owner selected account 267653922622, us-east-2, seven-day retention and a $5/month alert. Deployment profile permissions, environment/host and alert recipient must be settled before applying infrastructure. No indefinite retention by accident. Redact before transmission, minimize payloads and restrict reader access. Budget alerts are notifications, not hard spending caps; control ingestion volume and query windows too.
- **Acceptance:** Issue #3 includes hosted delivery validation: a known application event must be discoverable by correlation ID, with expected JSON fields, redaction and configured retention. Test collector interruption/recovery and disclose loss/duplication behavior. Local unit tests alone do not complete this requirement.
- **Alternatives:** Grafana Cloud and Datadog add a second vendor/account; not selected. Self-hosted storage adds operations that the owner wants the hosted platform to handle. Direct SDK calls in application logging couple runtime behavior to network delivery; use the agent instead.
- **Consequences:** Local development remains credential-free. Agent/install/IAM/rotation deployment work and a real AWS smoke test remain pending. Platform selection is complete; no claim is made that logs already arrive in CloudWatch.
