## Artifact manifest contract for implementation

For each externally stored dataset or evidence bundle, record an immutable artifact ID, schema/version, origin (`synthetic`, `testbed` or authorized operational source), producing commit/configuration, time, byte size and SHA-256, location/version, permitted uses, owner/access, retention/deletion rule and sensitivity. Include cohort/split and ground-truth references where applicable, without placing hidden answers in runtime manifests. The manifest must distinguish access-controlled metadata from secrets and permit a consumer to verify exact bytes before use.

S8 storage work must define scoped identities, encryption/access and retention controls, versioned upload/download, checksum verification, missing/unavailable behavior, backup/restore, and a no-dispatch reproduction path. Review actual source/retention terms before copying. A content hash detects byte changes; it neither authorizes use nor proves an artifact is the latest version.

## Safe migration sequence

1. Enumerate individual candidate files and inbound links/consumers, owner, reader, classification and retention; record the proposed canonical replacement and whether the file is active, historical, generated or a frozen input.
2. Confirm the destination exists and the intended readers can access it. Copy without modifying bytes; compare hashes and manifest identities. For historical reports, verify the recorded checkout and rescore/reproduction command before changing a path.
3. Update consumers and navigation; run link checks and affected tests/reproduction. Protect held-out labels from runtime and retrieval. Do not require credentials for ordinary tests.
4. Remove only a redundant tracked copy whose replacement is verified and approved. Keep original evidence/decisions when needed to reproduce or explain history. Revert the consumer to the old path if verification fails. Git history remains intact; removing working-tree files does not shrink existing Git history.
