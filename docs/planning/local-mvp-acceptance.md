## Metrics and missing results

Reuse [#39's actual-output projection and scorer](../architecture/investigator-evaluation.md#scores-and-denominators) and [#14's rubric](../architecture/development-evaluation.md#metrics-and-denominators). Every rate retains numerator, denominator and a null value for denominator zero. `evaluation.local_mvp.assess_rate` demonstrates threshold comparison: an empty denominator is `unmeasured`, and a missing threshold is `threshold_pending`; neither passes. No new measurement or historical rescore is made by the planner.

| Measure | Numerator / denominator or aggregation |
| --- | --- |
| Schema validity | Completed valid assessment candidates / all planned model-arm attempts |
| Cause / service accuracy | Exact primary label / service matches on answerable cases / all answerable planned model-arm attempts; failed/missing/malformed attempts score false; insufficient-evidence cases are excluded |
| Assessment accuracy | Expected supported/abstained candidate status matches / all planned model-arm attempts; preserve runtime publication/review status separately |
| Structural abstention | Valid abstention with reason, named missing evidence and actual unavailable-source gaps / all insufficient-evidence model-arm attempts; human adequacy review remains separate |
| Citation validity | Authorized, revision-bound valid claim references / all claim references in valid reports; repeated references across claims count separately; missing output does not manufacture references |
| Timeline completeness | Exact supplied snapshot reference sequence / all applicable planned attempts; source incompleteness is recorded independently |
| Delivered timeline validity | Authorized observed-time/ID order, source revisions, event/collection times and candidate agreement where applicable / all applicable planned attempts |
| Human unsupported claims | Owner-judged unsupported claims / owner-judged determinate claims across all integrated outputs; count indeterminate/unreviewed claims separately and retain uncited/invalid-reference claims. Single-reviewer provenance is explicit; no inter-rater agreement is inferred |
| Completion / reliability | Terminal completed investigations or produced bundles / all planned attempts per arm; report supported, abstained and review-pending publication separately from completion |
| Elapsed latency | Monotonic time from receipt of brief/submission until terminal result, including queue/dependency/review waits applicable to that workflow; retain observed time for every attempt, with stopped-task bounds. Report nearest-rank p95 (`ceil(0.95*n)`) and denominator; no successful-only latency gate |
| Tokens / tools | Actual input/output tokens, model/tool counts per attempt and totals; report known/partial/unknown counts; zero tools in LLM-only, no model tokens in evidence bundle |
| Estimated cost | Versioned complete-usage estimate per attempt and total; scalar gate uses the maximum per-attempt estimate. Unknown/partial usage remains unknown and retains the conservative reservation; reservation and invoice are separate |

Failed, cancelled, expired, unstarted planned, missing and malformed attempts stay in reliability and applicable diagnosis denominators. Record unstarted tasks explicitly as incomplete scheduled work; do not fabricate a runtime job/status or elapsed measurement. Source-incomplete attempts remain visible even if execution completes; distinguish expected capture gaps from a failed source. Review-pending candidate label scores are exploratory until support review completes and do not promote operational publication. Unknown latency/cost prevents the corresponding gate from passing; show bounded reservations separately. Do not replace missing measurements with zero or silently drop them. Exact labels and valid IDs do not prove cause/support.

The numeric template diagnostic thresholds apply to the integrated arm's applicable S7 actual-provider metrics; S6 uses the local mechanical/completeness/security requirements in the delivery matrix. The evidence-bundle completion/timeline/latency limits also apply where meaningful. LLM-only is a measured reference with the same failure accounting, not a requirement to invent evidence/citations to pass integrated thresholds. Report nonapplicable reference metrics explicitly rather than passing or counting them as zero. #64 must report these applicability decisions with its raw scores. Boundary safety is a separate mandatory veto, never an average or tunable threshold.
