# Local MVP acceptance protocol

Issue [#63](https://github.com/krispykrits/TRACE/issues/63) prepares the Sprint 6 acceptance gate before measurement. The versioned [protocol](../../evaluation/local_mvp_protocol_v1.json) defines the cohort, arms, review policy and stop conditions. The [decision template](../../evaluation/local_mvp_decisions_v1.json) deliberately leaves owner-dependent values null. No numeric release threshold, run authorization, reviewer endorsement or zero-spend assumption has been supplied. This is protocol preparation; #64 executes comparisons, #65 collects actual review, #66/#67 verify recovery/security, and #68 owns the release decision.

## Prepare a dry run

From the repository root, with the [locked development environment](../development.md#setup-and-first-run):

~~~sh
uv run --locked python -m evaluation.local_mvp --output /tmp/trace-local-mvp-plan-v1
~~~

Choose a new directory whose parent already exists. Exit 1 means a valid dry-run manifest was saved with explicit blockers; exit 0 means the supplied planning inputs and hash bindings are complete for review; exit 2 means invalid inputs or output failure. These exit codes never report acceptance or dispatch a model/tool/process. The default draft exits 1, with unknown cost and no measured usage. Mode-0700 output contains exclusive mode-0600 `protocol.json`, `decisions.json` and `manifest.json`, written in that order. Existing outputs are never overwritten. A partial directory without its final manifest is incomplete.

The retained [draft dry-run manifest](../../evaluation/reports/local_mvp_preparation_v1/manifest.json) records these unresolved inputs with zero provider calls. Its adjacent protocol/decision copies preserve exact input bytes. This is preparation evidence only. To reproduce its bindings, use a checkout whose listed source bytes match; current-source exploration uses a fresh output directory and can legitimately have different hashes.

Copy the decision template to a private working location, fill actual owner decisions, and pass `--decisions /absolute/private/decisions-v1.json`. Run once to obtain `binding`; then record `approval` with `owner`, aware ISO `recorded_at`, durable `reference`, and the exact `protocol_sha256`, `decisions_sha256`, `source_snapshot_sha256`. The decision hash covers canonical decision JSON excluding `approval`, avoiding a circular hash. The manifest also binds the original decision bytes and complete approval record separately. Missing approval or mismatches remain blockers. Supplied provenance records are trusted local inputs, not authenticated authority or a substitute for independent current source/transmission checks.

Approve before the applicable acceptance measurement. A changed threshold, repeat, budget, coverage or permission requires a new decision revision, approval and applicable run. A changed cohort, arm, metric or rubric requires a new protocol revision. A changed implementation, lock, development truth or corpus changes the source snapshot and requires renewed approval. Retain original plans/runs/judgments unchanged. #64 must copy these exact inputs and bind the plan manifest hash into every run and attempt before dispatch; it must revalidate actual grants, spending, input hashes and configuration and stop on mismatch. This planner does not implement #64's executor.

## Scope, identity and arm order

The task is a read-only investigation of the synthetic Order → Payment test environment over its recorded incident window. Use the four `mvp-suite.v1` cases at seed 17: regression `c01`, dependency degradation `c02`, missing Payment capture `c03`, ambiguous mechanism `c04`. Notification deployments and unchanged Payment deployment records are deliberate noncausal distractors. All belong to `order-payment-timeout-v1`; related cases/repeats are not independent samples. No validation/final-test labels are generated or accessed.

The dry-run source inventory hashes recursive runtime/evaluator/script Python, pyproject/lock, the explicit development truth manifest, development corpus manifest/documents, the Sprint 5 boundary protocol and the metric/review guides. Corpus `trace-knowledge-development.v1` carries per-document revisions/hashes; answer-bearing fictional history must still pass current retrieval/provider policy. The planner reads no credentials, private journal/profile, operational report or held-out label directory. Before actual comparisons, #64 must additionally freeze common brief bytes, captured operational input bytes/UTC times, actual selected corpus/index generations and admitted source revisions. Source hashes identify bytes, not permissions.

| Arm | Permitted inputs and deliberate differences |
| --- | --- |
| LLM-only reference | Common observed-only brief; same approved provider/model/API/configuration and model budget ceilings; no operational snapshot, retrieval, tools or shared history. Record its distinct prompt bytes/hash; uncertainty or abstention may be appropriate. |
| Deterministic evidence bundle | Same task/data identity, authorized observed snapshot, source completeness, provenance and UTC/ID timeline. No predicted cause, model text or next action. Diagnosis, assessment-schema and claim-support metrics are nonapplicable. Model tokens/cost are nonapplicable; no model calls are made. |
| Integrated RAG/tools | Same brief/task/capture plus current-authorized snapshot, development corpus and bounded read-only tools. Record integrated prompt, tool/policy/configuration versions and actual evidence channels/consumption. |

Both model arms use the selected Azure Luna configuration and identical maximum model-call/input/output/deadline ceilings; LLM-only has no tool channel. Actual usage can differ. Serial execution rotates `[llm_only, evidence_bundle, rag_tools]` by `(case_index + repeat_index) modulo 3`; this fixes order before measurement and avoids shared conversation/state. Owner-selected repeats determine the exact schedule. Report paired per-case/repeat outcomes and aggregate each arm separately; do not infer statistical independence from repeated templates. Report runtime/provider-reported model separately from configured dated model; the dated version is unconfirmed when the provider reports only a family name.

Run the six [Sprint 5 mechanical boundary cases](../../evaluation/investigator_protocol_v1.json) separately: malformed report, timeout, unauthorized citation, hostile instructions, answer-marker rejection and source failure. #66/#67 extend representative recovery/access/transmission/disclosure checks. Include every planned boundary result in its safety report; exclude deliberate faults from the four-case diagnostic denominators. A critical boundary failure vetoes release regardless of average quality. Offline hostile-input checks do not establish actual-model resistance.

## Metrics and missing results

Reuse [#39's actual-output projection and scorer](../architecture/investigator-evaluation.md#scores-and-denominators) and [#14's rubric](../architecture/development-evaluation.md#metrics-and-denominators). Every rate retains numerator, denominator and a null value for denominator zero. `evaluation.local_mvp.assess_rate` demonstrates threshold comparison: an empty denominator is `unmeasured`, and a missing threshold is `threshold_pending`; neither passes. No new measurement or historical rescore is made by the planner.

| Measure | Numerator / denominator or aggregation |
| --- | --- |
| Schema validity | Completed valid assessment candidates / all planned model-arm attempts |
| Cause / service accuracy | Exact primary label / service matches on answerable cases / all answerable planned model-arm attempts; failed/missing/malformed attempts score false; insufficient-evidence cases are excluded |
| Assessment accuracy | Expected supported/abstained candidate status matches / all planned model-arm attempts; preserve runtime publication/review status separately |
| Structural abstention | Valid abstention with reason, named missing evidence and actual unavailable-source gaps / all insufficient-evidence model-arm attempts; human adequacy review remains separate |
| Citation validity | Authorized, revision-bound valid claim references / all claim references in valid reports; repeated references across claims count separately; missing output does not manufacture references |
| Timeline completeness | Exact supplied snapshot reference sequence / all applicable planned attempts; source incompleteness is recorded independently |
| Delivered timeline validity | Authorized observed-time/ID order, source revisions, event/collection times and candidate agreement where applicable / all applicable planned attempts |
| Human unsupported claims | Agreed unsupported claims / agreed determinate independent human-reviewed sampled claims; exclude and count disagreements/indeterminate/unreviewed claims; retain uncited/invalid-reference claims separately |
| Completion / reliability | Terminal completed investigations or produced bundles / all planned attempts per arm; report supported, abstained and review-pending publication separately from completion |
| Elapsed latency | Monotonic time from receipt of brief/submission until terminal result, including queue/dependency/review waits applicable to that workflow; retain observed time for every attempt, with stopped-task bounds. Report nearest-rank p95 (`ceil(0.95*n)`) and denominator; no successful-only latency gate |
| Tokens / tools | Actual input/output tokens, model/tool counts per attempt and totals; report known/partial/unknown counts; zero tools in LLM-only, no model tokens in evidence bundle |
| Estimated cost | Versioned complete-usage estimate per attempt and total; scalar gate uses the maximum per-attempt estimate. Unknown/partial usage remains unknown and retains the conservative reservation; reservation and invoice are separate |

Failed, cancelled, expired, unstarted planned, missing and malformed attempts stay in reliability and applicable diagnosis denominators. Record unstarted tasks explicitly as incomplete scheduled work; do not fabricate a runtime job/status or elapsed measurement. Source-incomplete attempts remain visible even if execution completes; distinguish expected capture gaps from a failed source. Review-pending candidate label scores are exploratory until support review completes and do not promote operational publication. Unknown latency/cost prevents the corresponding gate from passing; show bounded reservations separately. Do not replace missing measurements with zero or silently drop them. Exact labels and valid IDs do not prove cause/support.

The numeric template thresholds apply to the integrated arm's applicable metrics; evidence-bundle completion/timeline/latency limits also apply where meaningful. LLM-only is a measured reference with the same failure accounting, not a requirement to invent evidence/citations to pass integrated thresholds. Report nonapplicable reference metrics explicitly rather than passing or counting them as zero. #64 must report these applicability decisions with its raw scores. Boundary safety is a separate mandatory veto, never an average or tunable threshold.

## Human review and owner decisions

Before measurement the owner must choose numeric thresholds for quality, reliability, elapsed p95 and estimated cost; repeat count; sampled claims per model arm; at least two independent reviewers per claim; and a positive minimum agreed determinate count per arm, no larger than the sample. Record local memory/disk limits, retention days and cleanup owner, plus versioned source/transmission and retention approval references. Implementation ceilings constrain valid settings but supply no acceptance targets.

After outputs exist, sample the declared first N claim bindings per model arm in case/repeat/claim-ID order, retaining exact report/citation/input/rubric hashes. Report the full population and sampled/reviewed/determinate fractions. If too few claims exist, preserve that shortfall as a blocker; do not manufacture claims, change N or replace an indeterminate claim. Each sample requires the declared independent human coverage and an identity/rationale/verdict. Review causal strength, uncertainty, competing evidence and missing sources under the existing rubric. Review abstention adequacy and next-check usefulness separately. Their actual judgments and unresolved objections inform #68's owner decision; this draft supplies no invented numeric semantic rubric threshold.

Preserve each original decision and any assistance provenance. Disagreement is explicit; a separate adjudication records identity/rationale and links the originals, while original agreed-rate results remain reproducible. An all-indeterminate sample has no support rate and cannot meet positive determinate coverage. Runtime support ports, AI fixtures, retrieval blanket judgments and the earlier guided all-indeterminate review supply no independent human decisions for these new outputs.

## Provider, spending and execution gates

Record actual deployment, model ID/dated version, Responses API revision, configuration, separate arm prompt revisions, tool and policy revisions in decisions before measurement. #64 must verify them against actual loaded bytes and metadata, including unknown reported version. Do not copy a past connector run's usage or spend as current accounting. The planner uses the repository's versioned `azure-luna-global-ceiling-2026-09-22.v1` reservation rates (250/750 nanodollars per input/output token); it does not fetch current prices or assert provider billing. A pricing change requires a new reviewed protocol/configuration snapshot.

With `r` repeats there are `12*r` planned attempts, including `8*r` model attempts. The projected model ceiling is `8*r * max_model_calls * (input_token_allowance*250 + output_token_cap*750)` nanodollars. Input allowance must cover all admitted instructions/context/history and provider framing under the [actual provider policy](../architecture/model-provider.md); #64 validates those bounds before dispatch. Correction/refinement/retry calls consume the same finite call budget. Evidence-bundle and scripted boundary controls make zero paid calls. No live boundary extension is included in this estimate or implicitly authorized. Schedule length is not a measured duration; deadlines are execution limits, not latency success targets.

The owner supplies the accounting month and timestamp, known prior spend, outstanding unresolved reservations, scope allowance and shared private journal reference. Unknown accounting blocks planning readiness. Projected scope must fit both the separately authorized scope allowance and monthly headroom; even the full scope allowance must fit headroom. The TRACE monthly cap is at most $20 and remains separate from Azure infrastructure/account billing. Do not read or mutate a journal during dry-run preparation. These are supplied snapshots; the actual executor must refresh accounting/authority immediately before admission and retain uncertain-attempt reservations across retries/restarts.

Record separately bounded live-run authorization and source/transmission/retention references with the approved hashes. Current policy/grants still gate every request/history/retry and saved output. Stop on any protocol/source/authority/configuration mismatch, critical source/transmission/evaluator/disclosure/read-only failure, unknown external attempt, spending/resource/deadline limit, cancellation or owner stop. Preserve all planned/attempted outcomes and unknown usage, reconcile uncertain dispatch before any explicitly approved retry, and perform no operational mutation.

The draft's missing inputs block acceptance execution. They do not block retaining this offline protocol and planner for review. Local MVP release, cloud delivery, the independent Operational Pilot, the final five-arm study and real production remediation retain their distinct [delivery gates](capstone-project-plan.md#releases-and-acceptance).
